# mariomos.com

A portfolio for a frontend engineer who builds design systems. The site is
also the artefact: it is built from its own tokens and its own component
library, and it annotates itself as you scroll.

## The idea

The work is the space between design and code — tokens, specs, redlines,
handoff. So the site looks like what that work produces: an annotated
specimen. Measurements sit in the margins, section boundaries carry their
own dimensions, and component states are labelled the way an inspect panel
labels them. The numbers in those marks are read from the spacing scale, so
a mark cannot disagree with the thing it measures.

Two switches in the header turn the annotation layer off and reveal the
12-column grid it is measured against.

## Tokens

`tokens/tokens.json` is the only place a value is authored. `npm run tokens`
generates:

| Output | Used by |
| --- | --- |
| `app/tokens.css` | every stylesheet, as CSS custom properties |
| `public/tokens.json` | the published distribution, linked from the site |

`lib/tokens.ts` reads the distribution back, which is how the annotation
marks and the component library render real values instead of copies.

Three kinds of token:

- **primitive** — the six colours, the spacing scale, the type scale.
- **semantic** — role aliases (`--c-text`, `--c-line`) that components
  reference. These are the only things that change between light and dark.
- **derived** — computed by the build. Either a documented blend, or a
  colour *solved* for contrast.

### Contrast is solved, not chosen

Every semantic role declares what it is for (`$use`: text, fill, line, mark,
surface). A role declared with `solve` is generated by blending toward ink or
paper in 1% steps until it clears the target in `$a11y` against its own
background, and it stops as soon as it passes:

```
solved  light/measure-text: #00A3C4 -> #057B98 (blended 29%)
solved  dark/measure-text:  #00A3C4 -> #00A3C4 (already passed)
```

The build then re-checks every role against the target its use demands, in
both schemes, and exits non-zero if one fails. A primitive cannot be edited
into an inaccessible pair without the build saying so. The resulting ratios
are published in the library's colour table.

## Layout

A 12-column grid. Content occupies columns 3–10; columns 1–2 are the
annotation margin. Below 900px the margin cannot hold a measurement without
becoming noise, so the grid collapses and the annotation layer drops to an
inline form.

## Type

- **Display** — Bricolage Grotesque, self-hosted as a variable font so the
  width axis is genuinely available. Headlines compress as the viewport
  narrows rather than wrapping into a ragged stack.
- **Body** — IBM Plex Sans. Measure capped at 68 characters, left-aligned.
- **Mono** — IBM Plex Mono, for real values only. A mono label above a
  heading is decoration; `--space-4: 16px` is information.

Nine sizes on a 1.25 minor third from 16px. Headlines step between those
sizes at breakpoints rather than interpolating off-scale.

## Motion

One orchestrated moment: on first load the annotation marks draw themselves
in over two seconds, then settle. After that, motion only answers actions.
The layer is styled to be correct without JavaScript — the boot script only
adds the draw-in, once per session, and honours `prefers-reduced-motion`.

## Running it

```bash
npm install
npm run dev      # regenerates tokens, then starts the dev server
npm run build    # regenerates tokens, then static-exports to out/
npm run tokens   # token build on its own, with the contrast report
npm run lint
```

The site is a static export (`output: "export"`), so `out/` is the whole
deployable. There is no server, which is why contact is links rather than a
form.

## Figures

Case-study sections opt into a figure by key (`figure: "pipeline"`), resolved
through a small registry in the case-study route.

`components/diagram/` holds inline SVG, styled from the same tokens as
everything else so it themes with the site rather than shipping two exported
images.

`components/demo/` holds interactive figures. The theme-swap demo defines its
three themes once, in TypeScript, and applies them as custom properties on the
mock's wrapper - so the token readout beside it reads the same object the
styles do. Two elements in the mock carry hard-coded values instead of tokens
and therefore do not re-theme; that is deliberate, and it is the point the
figure exists to make. All three themes were contrast-checked before shipping.

## Layout of the repo

```
tokens/tokens.json        the source of truth
scripts/build-tokens.mjs  solver, generator, contrast guard
styles/                   base, layout, components, annotations, site
components/annotation/    the measurement layer
components/diagram/       inline SVG figures, themed from tokens
components/demo/          interactive figures
components/ui/            the primitives the site is built from
app/components/           the live library, documented from those primitives
lib/content.ts            all copy, with placeholders marked TODO(...)
```

## Placeholders

`lib/content.ts` marks unfinished copy with `TODO(...)`, which renders as a
magenta dashed block on the page so it cannot ship unnoticed. Search for
`TODO(` to find them all.
